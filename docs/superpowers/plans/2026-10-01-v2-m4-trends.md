# Stack Break Lab v2 — M4 Trends Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Accumulate per-target history (`results/timeline.json`) and ship a `/trends/` page — verdict-change timelines and latency trends drawn as hand-rolled SVG, with a quarterly summary line and a quarterly-report workflow stub.

**Architecture:** `scripts/update-timeline.mjs` appends `{d, v, t}` per target after every evidence run (idempotent; `--rebuild` reconstructs from the dated `probe.json` archive — the same resilient pattern as `update-history.mjs`). The page at `trends/index.html` follows the refreshed design system (theme.css cascade, page-header pattern) and renders SVG stripes/sparklines client-side from the JSON — zero chart libraries, mainland-safe. Reuses the verified per-page-family workflow: computed-style + screenshot checks per section.

**Tech Stack:** Node ≥18 ESM + `node:test`; vanilla ES5-style browser JS; hand-authored SVG; Playwright.

**Spec:** `docs/superpowers/specs/2026-09-29-v2-dual-taxonomy-reports-community-design.md` (§1.5 timeline.json, M4 row of §7, v2.1 addendum nav note).

## Global Constraints

- Zero new dependencies; no chart libraries (self-contained, mainland-reachable).
- `timeline.json` is append-only data: weekly step appends; `--rebuild` re-derives the whole file from `results/<date>/probe.json` (source of truth stays the dated archive).
- Trends page follows the v2.3 theme: theme.css cascade + page-header pattern + solid band rhythm; verdict colors are the only chromatics on the stripes.
- Main nav stays Home · Stack · Product (maintainer-fixed); Trends is linked from the home reports section, Stack page, and footer — not the top nav.
- Quarterly PDF = workflow_dispatch stub only (prints the intended command; real generation deferred until data accumulates).
- Historical evidence under `results/` is never rewritten; timeline is derived.

### Task 1: Timeline core + updater (TDD)

**Files:** Create `scripts/update-timeline.mjs`, `tests/unit/update-timeline.test.mjs`

**Interfaces:**
- `appendPoint(timeline, probeDoc)` → new timeline (pure; dedupes by date, keeps targets ordered by first appearance).
- `buildTimeline(resultsDir)` → `{ generatedAt, targets: { id: [ { d, v, t } ] } }` from every dated `probe.json`.
- CLI: `node scripts/update-timeline.mjs [--rebuild]` — default appends today's probe if missing; `--rebuild` regenerates fully. Writes `results/timeline.json`.

- [ ] Failing tests: append idempotence (same date twice → one point), verdict/t fields copied, rebuild from two fixture dirs yields sorted history, unknown verdicts tolerated.
- [ ] Implement; tests PASS; backfill via `--rebuild` (18 runs); commit `feat(trends): timeline accumulator with rebuild`.
